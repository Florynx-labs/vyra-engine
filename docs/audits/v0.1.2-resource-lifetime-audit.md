# VYRA Engine v0.1.2 Resource Lifetime Audit

**Date:** 2026-08-09  
**Version:** v0.1.2 Stabilization  
**Scope:** Complete GPU resource lifecycle analysis

---

## Executive Summary

This audit analyzes the GPU resource lifecycle management in the VYRA Engine RHI layer to ensure proper destruction order, prevent use-after-free, eliminate double destruction, and remove stale handles.

## Current GPU Resource Inventory

### Vulkan Context Resources
- **VkInstance**: Managed by VulkanContext
- **VkDebugUtilsMessengerEXT**: Managed by VulkanContext
- **Status**: ✅ Proper destruction order implemented

### Vulkan Device Resources
- **VkPhysicalDevice**: Query-only, no ownership
- **VkDevice**: Managed by VulkanDevice
- **VkQueue**: Retrieved from device, no explicit destruction
- **Status**: ✅ Proper lifecycle management

## Destruction Order Analysis

### Current Implementation Order (VulkanSwapChain::Shutdown)
```
1. Fences
2. Semaphores (render finished)
3. Semaphores (image available)
4. Command pool
5. Framebuffers
6. Render pass
7. Image views
8. Swapchain
```

### Correct Vulkan Destruction Order
```
1. Command buffers (implicit via command pool)
2. Command pools
3. Framebuffers
4. Image views
5. Render pass
6. Pipelines (if applicable)
7. Pipeline layouts
8. Shader modules
9. Semaphores
10. Fences
11. Swapchain
12. Device
13. Instance
```

### Issues Identified
1. **SwapChain destroys render pass**: Should use RHIRenderPass abstraction
2. **SwapChain manages command objects**: Should use RHI abstractions
3. **No validation of handle state**: Could attempt double destruction
4. **No use-after-free detection**: Stale pointers possible

## Use-After-Free Risks

### High Risk Areas
1. **Entity raw Registry pointer**: Entity holds raw Registry* pointer
2. **RHI raw device pointers**: Many functions take void* device parameters
3. **Vulkan raw handle access**: Direct VkHandle access throughout code
4. **Scene cloning**: Deep copy may not validate all references

### Medium Risk Areas
1. **Shader module access**: Pipeline holds raw shader module pointers
2. **Buffer access**: Renderer holds raw buffer pointers
3. **Swapchain image access**: Direct image array access

## Double Destruction Risks

### Current Vulnerabilities
1. **No handle state validation**: VkHandle values not checked before destruction
2. **No null check after destruction**: Handles not set to VK_NULL_HANDLE consistently
3. **Shared ownership unclear**: Some resources may have multiple owners

### Mitigation Required
1. Add handle validation before destruction
2. Ensure VK_NULL_HANDLE assignment after destruction
3. Clarify ownership semantics for shared resources

## Stale Handle Risks

### Identified Issues
1. **No versioning**: Handles are simple values, no generation counters
2. **No lifecycle tracking**: No way to know if a handle is still valid
3. **No reference counting**: Shared resources lack reference counting

## Recommendations

### Immediate Actions (v0.1.2)

#### 1. Enhance VulkanSwapChain with RHI Abstractions
- Replace direct Vulkan command objects with RHI abstractions
- Use RHIRenderPass instead of managing VkRenderPass directly
- Maintain consistent abstraction layer

#### 2. Add Handle Validation
- Implement handle state checking before destruction
- Add VK_NULL_HANDLE assignment after destruction
- Add validation in debug builds

#### 3. Improve Resource Manager
- Extend VulkanResourceManager for swapchain resources
- Add reference counting for shared resources
- Implement handle versioning

#### 4. Use-After-Free Detection
- Add debug mode handle validation
- Implement stack-based handle tracking
- Add memory poisoning in debug builds

### Architecture Improvements

#### 1. Smart Handle System
- Implement generation-based handles
- Add handle version validation
- Prevent stale handle access

#### 2. Reference Counting
- Add shared_ptr where appropriate
- Implement custom reference counting for GPU resources
- Clarify ownership semantics

#### 3. Lifecycle Tracking
- Add resource state tracking
- Implement lifecycle validation
- Add debug logging for resource lifecycle events
